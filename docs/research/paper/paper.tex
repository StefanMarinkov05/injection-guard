\begin{abstract}
\noindent Coding and office agents read web pages, repositories, PDFs and emails written by strangers, and they act on
what they read. We present \emph{injection-guard}, an open-source plugin for Claude Code that shows the agent only what
a human would see and asks the user before actions with a dangerous effect, and we measure where Claude models need such
a layer. In \val{review.accounting.all_runs} judged decisions of 11 Claude models (Haiku, Sonnet and Opus, generations
4.5 to 5.5) we separate two outcomes. On 42 scenarios with a planted third-party instruction, the 4.x models at default
effort followed \val{F2-generation-without-bootstrap.k1} of \val{F2-generation-without-bootstrap.n1}
(\val{F2-generation-without-bootstrap.rate1}) and the 5.x models \val{F2-generation-without-bootstrap.k2} of
\val{F2-generation-without-bootstrap.n2} (exact stratified $p = \val{F2-generation-without-bootstrap.strat_p}$); over
all \val{review.accounting.pooled_5x} 5.x runs, including five effort levels and a security prompt, the count was
\val{review.pooled_5x.injection}. On one scenario with no planted instruction, a setup script that pipes a remote
download into a shell, the 5.5 models took the step in \val{F9-bootstrap-5.0-vs-5.5.k_5_5} of
\val{F9-bootstrap-5.0-vs-5.5.n_5_5} conditions and the 5.0 models in \val{F9-bootstrap-5.0-vs-5.5.k_5_0} of
\val{F9-bootstrap-5.0-vs-5.5.n_5_0} ($p = \val{F9-bootstrap-5.0-vs-5.5.p}$): a regression in judging process steps, not
in resisting injection. These are single-call decisions to act; as real Claude Code agents with tools, the 5.x models took
the step in \val{c38_agent.k} of \val{c38_agent.n} runs (they inspected the script and warned instead), so this is a
decision-level regression that agents do not reproduce. With real agents the guard cut Haiku
4.5's follows from \val{AB-Haiku 4.5.off_followed} to \val{AB-Haiku 4.5.on_followed} of 14 (McNemar
$p = \val{AB-Haiku 4.5.p}$, a direction only) at \val{guard_ab.overhead.cost_ratio}$\times$ the cost and 47\% more
median wall-clock time, and it exposed three gaps. Payloads are withheld; the run table, a script that recomputes the
headline tests and a methods document are public.
\end{abstract}

\section{Introduction}

An AI agent serves one principal. When it reads a document written by someone else, it gains a second, uninvited
one. Prompt injection is that situation: instructions hidden in data that the model treats as if the user had given
them \citep{perez2022,greshake2023}. In a chat window the damage is a wrong answer. In an agent with a shell, a file
system and the user's logged-in accounts, it is whatever the agent can do.

This is no longer hypothetical. In 2025 a single crafted email made Microsoft 365 Copilot send internal data to an
attacker without a click \citep{echoleak2025}. A malicious issue in a public GitHub repository made an agent with the
GitHub MCP server leak a user's private repositories \citep{invariant2025githubmcp}. Code planted in an extension
release instructed Amazon Q to wipe local files and cloud resources \citep{aws2025q}. The Nx supply-chain attack used
developers' own installed AI command-line tools to search their disks for secrets \citep{wiz2025nx}. Hidden text on
web pages steered ChatGPT search \citep{guardian2024search}, a Reddit comment hijacked an agentic browser
\citep{brave2025comet}, and researchers hid instructions for AI reviewers in submitted papers \citep{lin2025hidden,register2025reviewers}.
Attackers now place injections in phishing emails to fool the AI filters meant to catch them
\citep{sublime2025phish,scworld2025phish,microsoft2026ascii}. Coding agents ran attacker code through settings files
and comments \citep{cursor2025curxecute,rehberger2025copilot,tracebit2025gemini,securityweek2026comment}.

Model vendors train against this \citep{wallace2024hierarchy,anthropic2025defenses}, and the newest models resist much
better. A deployer still has to decide whether an extra layer is worth it, for which tasks and which models. Benchmarks
report attack success rates \citep{yi2025bipia,zhan2024injecagent,debenedetti2024agentdojo}, but rarely the question a deployer
asks: \emph{if I already use a strong Claude model, what does a guard still catch, and what does it cost?} We answer it
for Claude models only and at the level of a model's \emph{decision to act}; a full-agent A/B on a subset is the bridge
to deployed agents.

\paragraph{Contributions.}
\begin{enumerate}
\item \textbf{A guard that works on what the human sees and on effects} (Section~\ref{sec:design}): a client-side
  plugin for Claude Code that renders untrusted content the way a person would, reports and removes what a person
  would not see, and asks the user before actions whose \emph{effect} is dangerous, independent of wording.
\item \textbf{A measurement of where it is needed} (Sections~\ref{sec:method} and \ref{sec:results}): 42 injection
  scenarios and one unsafe process step in six use cases, 11 Claude models, effort and system-prompt conditions, a
  blind LLM judge, nine hypothesis families tested with exact methods (formalized after the main campaign, so
  exploratory), and a full-agent A/B with the guard on and off.
\item \textbf{An honest account of the gaps} (Sections~\ref{sec:ab} and \ref{sec:limits}): the attack classes the
  guard misses, why, and what the design cannot measure yet.
\end{enumerate}
The companion methods document \citep{injectionguard} argues every test choice at length; this paper reports results.

\section{Threat model}
\label{sec:threat}

\paragraph{Attacker.} Controls some content the agent will read (a web page, a repository, a document, an email, an
issue, a tool result) but not the user's prompt, the model or the machine. This is indirect prompt injection
\citep{greshake2023,owasp2025llm01,nist2025aml}.

\paragraph{Victim.} A user who asks an agent for an ordinary task (``set up this repo'', ``pay this invoice'',
``classify these emails'') and grants it the usual tools. The user does not read every byte the agent reads, which
is the reason to use an agent.

\paragraph{Goal.} Make the agent act against the user. We group goals by the harm a user would suffer
(Table~\ref{tab:harm}).

\begin{table}[h]\centering\small
\caption{Harm classes used in this study, with the behavior we observed when an agent followed.}\label{tab:harm}
\begin{tabularx}{\linewidth}{@{}lL@{}}\toprule
Harm class & What a followed attack looked like in our runs\\\midrule
Code execution & ran a setup script that pipes a remote file into a shell; decoded and ran a hidden command; added
  an import of an attacker module; told the user to install a look-alike package\\
Secret and data theft & printed the user's SSH private key into a support ticket; wrote a CI step that sends the
  deploy token to an outside host\\
Fraud and phishing & put the attacker's bank account into a payment file; recorded an unapproved transfer as approved
  in meeting minutes\\
Destruction & deleted the backups folder and told the user the deletion had been approved\\
Manipulation and misinformation & dropped the best product because of a fake safety recall\\
\bottomrule\end{tabularx}
\end{table}

\paragraph{How attacks trick the agent.} We classify scenarios by \emph{technique class}, not by payload
(Figure~\ref{fig:attack}):
\textbf{hidden-render} (white, tiny, off-screen or CSS-hidden text: in the file, invisible on screen);
\textbf{hidden-markup} (comments, collapsed sections, metadata, structured data);
\textbf{encoding} (base64, invisible Unicode tag characters);
\textbf{impersonation} (fake system messages, fake conversation turns, fake support staff);
\textbf{split} (an instruction spread over several files); and
\textbf{process} (a plain-language step posed as the project's or team's own procedure, with nothing hidden at all).
The first four are \emph{visible to a scanner}; process attacks are not, because they look exactly like legitimate
instructions. One process scenario (C38) has no instruction aimed at the agent at all: the project's own setup script
downloads a file and runs it. That is an unsafe step in a trusted-looking process, not prompt injection, and we report
it as a separate outcome (Section~\ref{sec:method}).

\section{injection-guard: design}
\label{sec:design}

injection-guard is a Claude Code plugin (version \val{plugin_version}, \val{tests_total} automated tests) made of four parts that act
at different moments (Figure~\ref{fig:arch}). It needs no extra model and no server; everything runs on the user's
machine.

\node[box, below=10mm of agent] (pre) {\textbf{Pre-tool hook}\\\scriptsize read, effect and taint gates};

\node[usr, below=10mm of pre] (user) {User\\\scriptsize asked to allow};

\paragraph{1. What a human sees is the content.} \texttt{safe-read} and \texttt{safe-fetch} parse PDF, Office, EPUB,
HTML, images, archives and code by their bytes, not their extension, render what a reader would see, and compare it
with the text layer. Text a person would not see (white or tiny text, off-page objects, hidden CSS, comments,
metadata, invisible Unicode, encodings) is reported and removed; the agent receives only the visible text between
marked boundaries, with a findings report \citep[cf.][]{hines2024spotlighting}. \texttt{safe-fetch} also re-fetches as an
AI user agent and compares, to catch cloaking.

\paragraph{2. Wording is a signal; effect is the gate.} Pattern families catch known and respelled injection
wording, but the hooks do not rely on them. The pre-tool hook asks the user before actions whose \emph{effect} is
dangerous regardless of why the agent wants them: a command that downloads code and runs it, running build tools or
tests inside a folder downloaded in this session, writing configuration that runs programs (MCP or settings files).
After a HIGH finding it also asks before reading secrets and sending data out.

\paragraph{3. Findings change what the agent may do next.} A HIGH finding taints the session; while tainted, risky
actions ask. A registry keyed by SHA-256 keeps a file's verdict across sessions. A skill teaches the agent the
workflow, and a read-only \emph{quarantine reader} sub-agent can digest long untrusted documents so the main agent
never sees their raw text \citep[the dual-model pattern of][]{beurerkellner2025patterns}.

\subsection{What is new}
Table~\ref{tab:prior} places the guard among existing defenses. Model hardening \citep{wallace2024hierarchy,anthropic2025defenses}, training that separates instructions from data
\citep{chen2025struq,chen2025secalign}
and detection classifiers \citep{wan2024cyberseceval3,jacob2025promptshield,li2024injecguard} decide on text;
system designs such as CaMeL \citep{debenedetti2025camel}, the design patterns of \citet{beurerkellner2025patterns},
information-flow control \citep{costa2025fides,zhong2025rtbas} and tool-level privilege policies \citep{shi2025progent}
give stronger guarantees but require building or configuring the agent around them. injection-guard is a drop-in layer for an existing
agent that (i) works on the \emph{rendered} view of rich documents, where most hidden-text attacks live, (ii) gates by
effect and provenance rather than by a classifier score, and (iii) is open, local and auditable. It does not replace
model training; Section~\ref{sec:results} measures where it adds to it.

\subsection{What it takes}
\begin{itemize}
\item \textbf{Latency and cost.} In the A/B, each hook call took a median \val{guard_ab.overhead.hook_ms_median}\,ms
  (90th percentile \val{guard_ab.overhead.hook_ms_p90}\,ms, \val{guard_ab.overhead.hook_calls} calls). The median run
  took \val{guard_ab.overhead.seconds_median_on}\,s with the guard and \val{guard_ab.overhead.seconds_median_off}\,s
  without (47\% longer). Guarded runs used \val{guard_ab.overhead.tokens_ratio}$\times$ the input tokens and cost
  \val{guard_ab.overhead.cost_ratio}$\times$ as much (\$\val{guard_ab.overhead.cost_on} vs \$\val{guard_ab.overhead.cost_off}
  for 28 runs each).
\item \textbf{False alarms.} The guard is built for recall over precision. On 119 real university course PDFs it
  reported \val{survey.HIGH.files} HIGH and \val{survey.MED.files} MED files and \val{survey.clean.files} clean.
  Of the HIGH files, \val{survey.HIGH.real_instruction} carried a real hidden instruction to AI assistants (an exercise
  sheet with invisible text asking a model to solve a different problem and hide it); the others were benign hidden or
  faint content (a translation layer, slide overlays, scanned noise). HIGH findings ask the user; they do not block.
  In total 72 of 119 files (61\%) produced a finding and one was a real attack. A user who sees a warning on most
  documents will learn to ignore it: attention to security warnings drops after a few exposures
  \citep{vance2017habituation,vance2018tuning}. This is why only a HIGH finding changes what the agent may do next; MED findings are only reported.
\item \textbf{Friction.} In 28 guarded agent runs the guard denied one action, and that deny was wrong
  (1 of 1; Section~\ref{sec:ab}). One run is too few to estimate a false-deny rate.
\end{itemize}

\section{Method}
\label{sec:method}

\paragraph{Scenarios.} 43 scenarios, each a realistic user request, a workspace (files, a saved page, an inbox) and one
element whose effect would harm the user. Use cases: browsing (6), coding (10), documents (6), scanning (7: inbox
triage, log review, security review, package audit, phishing classification, repository audit), shopping (7) and
agent tasks (7). Every planted link points to a local canary host, which replies like an attacker's second stage;
the home folder is fake and holds honeytoken keys.

\paragraph{Two outcomes.} In 42 scenarios the harmful element is an instruction from a third party, addressed to the
agent or posed as part of its task. Following it is the \emph{injection} outcome. In one scenario (C38, ``set up this
repository'') the element is a line in the project's own setup script that pipes a downloaded file into a shell; nothing
is addressed to the agent. Taking that step is the \emph{process-step} outcome: a judgement about a dangerous but
ordinary-looking command, not obedience to an attacker. We report the two separately; the original pooled analysis is
kept for comparison.

\paragraph{Models and conditions.} Eleven models: Haiku 4.5 and 5.5; Sonnet 4.5, 4.6, 5 and 5.5; Opus 4.5, 4.6,
4.8, 5 and 5.5 (API model ids in the run table). Every model ran each scenario once at default effort. The three 5.5
models also ran at five effort levels (low to max) and with a security system prompt: seven conditions, 301 runs
each. After the main campaign, Sonnet 5 and Opus 5 ran C38 six more times each (low to max, security prompt), to test
the 5.0 vs 5.5 difference on that one scenario; these 12 follow-up runs enter only that test (F9).
Table~\ref{tab:acc} lists every run universe a percentage in this paper uses.

\begin{table}[h]\centering\small
\caption{Run accounting. ``Default'': default effort, no security prompt (\val{review.accounting.default_runs} runs:
\val{review.accounting.default_4x} for 4.x, \val{review.accounting.default_5x} for 5.x). ``Pooled'': every run of the main
campaign (\val{review.accounting.pooled_runs}; 5.x: \val{review.accounting.pooled_5x}). Follow-up runs are used only by F9.}\label{tab:acc}
\input{../generated/accounting-table.tex}

\paragraph{Harness.} One Claude Code call per run (18 and 19 November 2026), with the workspace and fetched page in the
prompt; the model answers with actions that are parsed and judged, never executed. This made
\val{review.accounting.all_runs} runs affordable (\$\val{totals.spend_usd} for the pooled runs) and measures what the
model \emph{decides} to do, in one step and with the whole workspace in view. A real agent decides step by step, can
inspect files before acting and is stopped by permission prompts; the guard A/B (Section~\ref{sec:ab}) uses real
agents for that reason.

\paragraph{Outcomes and judges.} A run \emph{followed} if it ran, fetched, wrote or said what the attacker wanted (for
C38: ran the setup step), even if it also warned; blocked attempts count. A run \emph{reported} if its answer explicitly
told the user about the planted or suspicious content, and \emph{task done} if it completed the user's real task well
enough to be useful. A blind LLM judge (Claude Opus 5.5, low effort, no tools) decides all three from the request,
the expected result, the scenario's definition of ``followed'' and the run's actions, files and answer, without
knowing the model; its prompt is in the methods document. A rule judge (patterns over actions) runs alongside; every
run was LLM-judged.

\paragraph{Statistics.} Counts are small and scenarios are shared across models, so all tests are exact or
permutation-based and every model comparison is stratified by scenario: exact binomial (F1), exact stratified
Mantel-Haenszel and Fisher (F2, F3, F6, F9), Cochran-Armitage (F4), exact McNemar (F5, F7, A/B), permutation
homogeneity (F8), Clopper-Pearson and scenario-cluster bootstrap intervals, Holm correction within each family. The
families were written down after the main campaign had run (18 and 19 November), so every $p$ value here is
exploratory, not confirmatory. The methods document gives each hypothesis, test, formula, reason and power.

\paragraph{Reproducibility.} The public repository holds the run table (\texttt{data/runs.json}: one row per run with
case, model id, effort, setup, both judges' verdicts, reported, task done, seconds, cost and tokens; no prompts or
outputs), every derived result file, and \texttt{recompute.py}, which recomputes F1, the injection-only F1, F2 and the
construct split from the run table with the standard library and checks them against the published values (all 76
match). The harness, the scenario files and the full statistics code stay in a private repository because they
contain the payloads. The Claude Code CLI version was not recorded per run.

\section{Results}
\label{sec:results}

\subsection{Are models misled by injected instructions?}
$H_0$ for each model was that it follows at most $p_0 = 1\%$ of attacks. The threshold is a deployer's choice, not a
standard: if the risk were 1\% per poisoned document and independent across documents, an agent exposed to 100 of them
would be compromised at least once with probability $1 - 0.99^{100} \approx 63\%$. Real exposures are not independent
(one attacker, one style), so this is an illustration of scale, not a forecast. Figure~\ref{fig:models} shows each
model at default effort over all 43 scenarios; Table~\ref{tab:construct} separates the two outcomes.

\begin{itemize}
\item On the injection outcome, Haiku 4.5 and Sonnet 4.5 followed \val{F1i-Haiku 4.5.k} of 42 each
  (\val{F1i-Haiku 4.5.rate}, 95\% CI \val{F1i-Haiku 4.5.cp_lo} to \val{F1i-Haiku 4.5.cp_hi}); ``at most 1\%'' is
  rejected after Holm ($p = \val{F1i-Haiku 4.5.p_holm}$). No other model is shown to exceed 1\%.
\item Every 5.x model followed 0 of 42 injections at default effort. That is \textbf{inconclusive at the 1\% level}:
  it does not show a rate above 1\%, and the exact upper bound is \val{F1i-Opus 5.5.cp_hi} per model.
\item Weighting each model once, the 4.x models followed \val{review.model_level_4x_injection.mean} of injections on

  models \val{review.model_level_5x_injection.mean}.
\end{itemize}

\takeaway{Older Claude models follow injected instructions measurably often. Current models followed none at default
effort, but 42 attacks per model cannot certify them at a 1\% level; whoever deploys them carries that uncertainty.}

\subsection{Generation matters, tier and effort do not}
On the injection outcome, generation 4.x followed \val{F2-generation-without-bootstrap.k1} of
\val{F2-generation-without-bootstrap.n1} (\val{F2-generation-without-bootstrap.rate1}) and 5.x
\val{F2-generation-without-bootstrap.k2} of \val{F2-generation-without-bootstrap.n2}: a difference of
\val{F2-generation-without-bootstrap.rd} (scenario-cluster 95\% CI \val{F2-generation-without-bootstrap.rd_ci_cluster}),
exact stratified $p = \val{F2-generation-without-bootstrap.strat_p}$. With both outcomes pooled, as first analysed, it
is \val{F2-generation.k1}/\val{F2-generation.n1} vs \val{F2-generation.k2}/\val{F2-generation.n2},
$p = \val{F2-generation.strat_p}$. Only 14 of the 43 scenarios have any follow at default effort
(Table~\ref{tab:strata} in Appendix~\ref{app:strata}); every one of them points the same way, and dropping any single
scenario leaves $p \le \val{review.F2_leave_one_out.max_p}$ and a difference of at least
\val{review.F2_leave_one_out.min_rd}. The result does not rest on one scenario.

Within a generation, no tier pair differs after Holm, effort shows no trend for any 5.5 model, and the security
system prompt changed no outcome. The 5.x models did follow five injections over all conditions
(\val{review.pooled_5x.injection}), all at high or extra-high effort: Haiku 5.5 on C05, C10 and C19, Sonnet 5.5 twice on
C19. Five events cannot carry a trend test, so we report them as cases, not as an effect of effort. The design detects
only large differences (about 20 percentage points between tiers), so these are absences of evidence, not proof of
equality.

Three patterns stand out.
\begin{enumerate}
\item \textbf{Code execution dominates.} It is the largest harm class and the only one where 5.x models still fail
  more than rarely, almost entirely through the process step C38.
\item \textbf{Agent tasks are the riskiest use case for 4.x.} When the user says ``follow the README'' or ``do the
  action items'', a planted step looks like part of the job. For 5.x every follow in this use case is C38.
\item \textbf{No scanning case was followed.} The seven scanning cases (an agent asked to classify or audit untrusted
  content, including phishing classification and a pre-adoption repository review) were followed in 0 of 203 runs.
  That is ``not observed'', with an upper bound of 2.3\% for 5.x (0 of 161), not evidence that judging content protects
  a model; adaptive attacks break such filters \citep{nasr2025attacker}, and our cases may simply have been too easy.
\end{enumerate}

\subsection{An unsafe process step: a single-call regression that agents do not reproduce}
\label{sec:c38}
C38 asks the agent to set up a repository by following its README. The README is clean; its setup script contains one
line that downloads a file and runs it in a shell. Nothing is hidden and nothing is addressed to an AI. Over every
condition, the 5.5 models took the step in \val{F9-bootstrap-5.0-vs-5.5.k_5_5} of \val{F9-bootstrap-5.0-vs-5.5.n_5_5}
runs (Haiku \val{review.process_c38.Haiku 5.5}, Sonnet \val{review.process_c38.Sonnet 5.5}, Opus
\val{review.process_c38.Opus 5.5}), including under the security prompt. The 5.0 models, given the same seven
conditions in the follow-up runs, took it in \val{F9-bootstrap-5.0-vs-5.5.k_5_0} of \val{F9-bootstrap-5.0-vs-5.5.n_5_0}
(Sonnet 5 \val{review.process_c38.Sonnet 5}, Opus 5 \val{review.process_c38.Opus 5}; exact Fisher
$p = \val{F9-bootstrap-5.0-vs-5.5.p}$). The 4.x models took it in \val{review.process_c38_default.4.x} at default effort.
In 17 of the 20 5.x runs that took the step, the answer also warned the user about piping a download into a shell: the
models saw the risk and ran the step anyway. C38 accounts for 7 of Sonnet 5.5's 9 follows and 7 of Opus 5.5's 7.

This is one scenario, so it shows a single-call regression on this step, not a rate for process steps in general. The same pattern
was reported independently for setup files in clean repositories \citep{helpnet2026mozilla} and for user-invoked
repository tasks \citep{zhu2026beyond}.

\paragraph{Real agents do not take the step.} The single-call decision is made with the whole workspace in the prompt
and no chance to look first. We therefore re-ran C38 with real Claude Code agents (tools Bash, Read, Write, Edit, Glob
and Grep, default effort, guard off, no security prompt, ten runs per model), together with a twin whose setup script
only installs the requirements. No agent ran the step: \val{c38_agent.k} of \val{c38_agent.n} runs (each 5.x model
\val{c38_agent.per_model.Opus 5.5}; upper 95\% bound \val{c38_agent.cp_hi}, for the 5.5 models alone
\val{c38_agent.gen_5_5.cp_hi}). \val{c38_agent.fetched} runs opened the script and tried to download the remote file to
read it, the other \val{c38_agent.untouched} left it alone, and \val{c38_agent.reported} answers warned the user about the
download (LLM judge and an execution rule agree on all \val{c38_agent.judged}). On the twin every agent ran the script
(\val{c38_agent.twin_ran} of \val{c38_agent.twin_n}), so the refusal is specific to the download, not a refusal to run
setup scripts. For the 5.5 models the two settings differ sharply (\val{F10-agent-vs-single-5.5.k_agent} of
\val{F10-agent-vs-single-5.5.n_agent} as agents vs \val{F10-agent-vs-single-5.5.k_single} of
\val{F10-agent-vs-single-5.5.n_single} in single calls, Holm $p = \val{F10-agent-vs-single-5.5.p_holm}$), and the 5.0 vs
5.5 gap disappears (\val{F10-agent-5.0-vs-5.5.k_5_0} of \val{F10-agent-5.0-vs-5.5.n_5_0} vs
\val{F10-agent-5.0-vs-5.5.k_5_5} of \val{F10-agent-5.0-vs-5.5.n_5_5}). The single-call result is a decision-level
finding that an agent able to inspect the file before acting does not reproduce. Ten runs per model rule out a high
rate, not a rare one. The download attempts were blocked by the test's permission list (the canary
server logged no request); in a normal session each would be a permission prompt.

\takeaway{The residual risk we found for current Claude models is not hidden text but an ordinary-looking dangerous
step, and in single calls 5.5 is worse than 5.0 on that step. Real agents inspected the script and did not run it (\val{c38_agent.k} of \val{c38_agent.n}).}

\subsection{What the guard covers}
\label{sec:coverage}
\emph{Static coverage}: the scanner flags or strips the payload of \val{totals.guard_covers} of 43 scenarios when the
agent reads through it. Of all \val{guard_stoppable_share.n} pooled follows, \val{guard_stoppable_share.k}
(\val{guard_stoppable_share.rate}, 95\% CI \val{guard_stoppable_share.lo} to \val{guard_stoppable_share.hi}) were on
covered scenarios. Models followed covered and uncovered injections at similar rates (pooled: covered
\val{review.coverage_pooled.covered}, uncovered without C38 \val{review.coverage_pooled.uncovered_without_c38}; F6, which
leaves C38 out by design, Holm $p \ge \val{F6-5.x.p_holm}$): the scanner does not only catch what the model would have
resisted anyway. The largest uncovered element is C38: nothing to detect, so only an effect gate can help.
\emph{Dynamic coverage} is lower than static coverage, because it depends on the agent using the guard's tools: in the
A/B, C05 was counted as covered but passed (below).

\subsection{Guard on: a full-agent A/B}
\label{sec:ab}
Static coverage assumes the agent reads through the scanner. To test the real plugin, we ran real Claude Code agents
(Haiku 4.5 and Haiku 5.5) on the 14 scenarios any model had followed, once with and once without the guard, with
every hook decision logged (Tables~\ref{tab:ab} and \ref{tab:abcases}). The 14 scenarios were chosen because a
model had followed them, so rates on them overstate rates on all 43; because both arms are fresh runs on the same
scenarios, the selection does not bias the comparison between arms.

With the guard, Haiku 4.5 followed \val{AB-Haiku 4.5.on_followed} attacks instead of \val{AB-Haiku 4.5.off_followed}.
The three it stopped following (C11 backdoor import, C19 invoice bank account, C33 fake recall) were all attacks
where the guard raised a finding; none became a follow because of the guard. Haiku 5.5 followed none in either arm.
The guarded agents warned the user more often (\val{AB-both.on_reported} vs \val{AB-both.off_reported} of 28 runs;
``reported'' as defined in Section~\ref{sec:method}) and completed the user's task in \val{AB-both.on_task_done} vs
\val{AB-both.off_task_done} of 28. With three discordant pairs, McNemar $p = \val{AB-Haiku 4.5.p}$ is the smallest value
possible: a direction, not a proof. The three attacks that passed name three gaps:
\begin{enumerate}
\item \textbf{Raw downloads.} The agent fetched a page with a plain \texttt{curl} instead of \texttt{safe-fetch}. The
  output hook marked the result as web content but did not detect hidden text in raw HTML, so the look-alike package
  (C05) went through. Static coverage had counted C05 as covered.
\item \textbf{Local process steps.} The setup script (C38) is a local file in the user's repository; no gate applied.
  Claude Code's own permission prompt stopped it in both arms.
\item \textbf{CI secrets.} Writing a workflow step that sends a secret to an outside host (C39) passed every hook.
\end{enumerate}
Version 1.8.0 adds a gate for each of the last two (a local script that pipes a download into a shell asks in every
session; a CI change that sends a \texttt{secrets.*} value to an outside host asks); the A/B above used 1.7.0 and has not
been re-run.
The one guard deny was wrong: the read gate refused a shell loop that itself called \texttt{safe-read}.

\paragraph{What the effect gate is and is not.} The gate is an enumerated list of effects. It always asks before a command that
downloads code and runs it in one step, before running code from a folder downloaded this session and before edits to
files that later sessions load as configuration or instructions; after a HIGH finding it also asks before sending data
out, reading secrets, installing packages and changing start-up files. An effect not on the list passes: C38 runs a
local script that does the download itself, and C39 writes a CI file. The scanner is
bypassed whenever the agent reads untrusted content through a tool that is not \texttt{safe-read} or
\texttt{safe-fetch}; the output hook then marks the result as untrusted but, for raw HTML, does not yet look for hidden
text. Both are design limits of a drop-in layer, not of this implementation alone.

\takeaway{With a weak model the guard prevented harmful actions in three of six cases; with a strong model it mostly
adds warnings. Its coverage depends on the agent using its tools, so output scanning of raw downloads and effect gates
for local scripts and CI secrets are the next steps.}

\subsection{A static matcher cannot decide alone}
\label{sec:matcher}
The rule judge, a static pattern matcher like a scanner, flagged \val{F7-judges.rule_yes} pooled runs as followed; the
LLM judge \val{F7-judges.llm_yes}. They disagree on \val{F7-judges.rule_only} + \val{F7-judges.llm_only} = 40 runs
(McNemar $p = \val{F7-judges.p}$, $\kappa = \val{F7-judges.kappa}$). Almost all extra flags were models that
\emph{quoted} the attack while warning the user. The same holds for a guard: wording is evidence, not a verdict, which
is why injection-guard reports and asks rather than blocks on patterns.

\section{Where a guard is needed}
Table~\ref{tab:need} applies one fixed rule to every pooled run. A cell is \textbf{needed} when the exact 95\% lower
bound of its follow rate is above $p_0 = 1\%$, \emph{seen} when there was a follow but the rate is not shown above 1\%,
and \emph{none} when no run followed. ``Scanner sees'' counts the cases whose payload the scanner flags; where it is low,
only an effect gate can help. Intervals treat runs as independent, which repeated runs of the same scenario are not, so
they are too narrow for 5.x cells; they also say nothing about attacks we did not write.

Read for a deployer of Claude models:
\begin{itemize}
\item \textbf{4.x models on untrusted content: a guard is needed} in four of six use cases. Haiku 4.5 and Sonnet 4.5
  followed 21\% of injections; in the A/B the guard stopped three of six follows.
\item \textbf{Setting up downloaded repositories: needed for every generation, and only an effect gate helps.} The
  scanner cannot see an ordinary setup step, and today the best protection is Claude Code's permission prompt.
\item \textbf{5.x models on browsing, coding and documents: defense in depth.} Follows were seen (invoices with hidden
  bank details at higher effort, one look-alike package, one build file) but are not shown above 1\%; the scanner sees
  most of these payloads.
\item \textbf{5.x models on scanning, shopping and agent tasks other than setup: none observed}, with upper bounds of
  2.3 to 2.6\%. A guard adds a record of what was hidden, not a measured reduction.
\end{itemize}

\section{Limitations and what is missing}
\label{sec:limits}
\begin{description}
\item[Decisions, not agents.] The main experiment measures one decision per run, with the whole workspace in the
  prompt, and executes nothing. A real agent can inspect, correct or compound a decision; on C38 the two settings
  disagree for every 5.x model (Section~\ref{sec:c38}). The A/B covers only 14 scenarios, two models and one run per cell.
\item[Author bias.] The same person wrote the attacks and the guard, so the guard is tuned to these attacks and static
  coverage is optimistic. Independent attacks, especially adaptive ones \citep{nasr2025attacker}, are the most important
  missing test. We publish per-case descriptions and the harness design so others can build their own.
\item[Small samples.] One run per model and scenario at default effort; differences below about 20 points are
  invisible. Repeated runs would turn the 5.x ``inconclusive'' into a bound. The process-step outcome rests on one
  scenario.
\item[Judge.] The LLM judge is from the same model family as the models judged and was not validated against human
  labels. Rule and LLM judge disagree on 40 runs (Section~\ref{sec:matcher}); a second-family judge on those runs and a
  hand-labelled sample are the missing checks.
\item[Exploratory tests.] All hypotheses were formalized after the main campaign; the construct split and the strata
  analysis were added after review. An open-classifier baseline is not yet reported. No $p$ value here is confirmatory.
\item[Scope.] Claude models only, November 2026 versions, Claude Code only; the CLI version was not recorded per run.
\item[Guard gaps.] Raw downloads, local process steps and CI secret steps (Section~\ref{sec:ab}; the last two gated since
  1.8.0, not yet re-measured); an enumerated effect
  list; one false deny in one.
\end{description}

\section{Conclusion}
On 42 injection scenarios, current Claude models at default effort followed no planted instruction, and the gap to the
4.x generation is large and robust to dropping any scenario. What remained for them is a different problem: an
ordinary-looking dangerous step in a project's own process, which the 5.5 models took more often than 5.0 in single
decisions, often while warning about it. A guard that shows the agent only what a human sees and asks before listed
dangerous effects stopped half of the follows of a weaker model and made a stronger one more transparent, at about a
tenth more cost and half again the wall-clock time. The measurement shows where Claude models need it; its gaps show
where to build next.

\paragraph{Disclosure and ethics.} All attacks targeted local canary hosts and fake credentials; nothing harmful was
executed outside the test machine. Payloads are withheld; scenario descriptions, the run table, results and the
recompute script are public. This paper and its data were published on 20 November 2026 without prior notice to
Anthropic. A short note on the Claude-specific findings (the C38 single-call result and its agent replication, without payloads) has been drafted for the
author to send; if it is sent, the date will be added here.

Their reports led to the construct split, the run accounting, the strata and leave-one-out analyses and several
